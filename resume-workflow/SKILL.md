# 简历优化与生成全流程

## 触发场景

当用户发送一条或多条招聘信息（含JD），表达"帮我分析""投哪个""出简历""对比一下"等意图时，自动进入本流程。

## 完整工作流

### Step 1：解析与匹配分析

拿到JD后，先逐条拆解岗位要求，与用户背景做逐项映射：

| JD 要求 | 状态 | 证据 |
|---------|:---:|------|
| 硬性条件（学历、专业、届次） | ✅/⚠️/❌ | 具体证据 |
| 核心职责 | | 可对应哪段经历 |
| 技能工具 | | 是否掌握 |
| 加分项 | | |

**关键判断原则：**
- 专业不对口且无直接经历对冲 → 高淘汰风险，如实告知
- 专业名称直接出现在JD中（如"交通运输"）→ 视为命中
- 有直接经历优于可迁移经历，可迁移优于无证据
- 多岗位时，按匹配度排序出优先级，不强推不匹配的

### Step 2：多岗对比（如有多个JD）

用表格快速对比关键维度：

```
| 排序 | 岗位 | 地段 | 核心匹配 |
|:---:|------|:---:|------|
| 🥇 | 最佳匹配 | | 命中理由 |
| 🥈 | 次选 | | |
| 不投 | 明显不匹配 | | 原因 |
```

### Step 3：资源库选材

从用户的「项目资源库」目录选取经历（目录组织规则见 [references/resource-library.md](references/resource-library.md)）。

关键动作：
- 先读用户环境下的 `基础信息/教育背景.md` 和 `基础信息/技能与证书.md` 获取固定模块
- 根据JD关键词匹配 `项目资源库/` 目录中的 `.md` 文件
- 选取 4-5 段最相关经历
- 不相关经历直接砍掉（零售不放技术岗、AI不放仓储岗）

### Step 4：写简历（.typ 文件）

使用 `typst-resume` skill 的模板结构生成 `.typ` 文件。参考 [assets/](assets/) 中的编译脚本。

**用词原则：**
- 每条经历描述贴合JD具体措辞，不写套话
- JD关键词必须落在一段经历的具体动作中，不能只堆在技能栏
- 动词如实：独立开发 ≠ 二次开发 ≠ 参与

**结构规则：**
- headline（求职意向）精简匹配岗位方向
- 经历按匹配度排序，最相关置顶
- 教育背景保留完整学历链（专科简写不删除）
- 技能栏只罗列工具/模型名，解释性文字放经历描述里

### Step 5：交付前检查

- [ ] 文件末尾双括号 `]]`
- [ ] 照片路径可访问，照片参数正确（box包裹 + height: 3.0cm + dy: -2.26cm）
- [ ] 教育背景含全部学历（硕士→交换→本科→专科）
- [ ] 头部下方有按岗位方向写的个人摘要（inset 右缩进，不压照片；技能区无重复的“核心优势”段）
- [ ] 右下角有作品集二维码（place 定位，1.6-2.0cm，打印可扫）
- [ ] 无中文引号冲突
- [ ] 实体性体验：每条核心经历能被面试追问验证
- [ ] 编译零警告，页数 = 1

**多版本简历矩阵**：按岗位方向维护通用版（如 通用1-供应链物流 / 2-交通轨道交通 / 3-AI数据 / 5-商务管培），投递时按岗选版本；同步更新时四份一起过“摘要措辞 + 二维码 + 页数”三项。

## 与 resume-jd-optimizer-cn 的关系

`resume-jd-optimizer-cn` 负责单个JD的深度匹配和内容重写（8步流程）。  
本技能负责**投递前的快速判断 + 多岗筛选 + 资源库驱动的批量产出**。  
如果用户给的JD非常详细且有明确简历优化需求，两个可以互补使用。

## 历史教训

来自用户反馈，必须遵守：

- ❌ 不要删除专科第一学历，用户在意完整学习经历
- ❌ 不要把"基于开源框架魔改"写成"独立开发"，如实标注角色
- ❌ 不要在两处重复写同样的工具名（如论文里写SBM，技能栏又写SBM），HR看重一次说清
- ✅ 论文价值在"做了什么、说明了什么"，工具名放技能栏统一展示
- ✅ 多段经历边界要清晰（如AI平台 vs 数据管道），避免叙事重叠
