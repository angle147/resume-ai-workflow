# 简历项目资源库使用指南

## 位置

在用户环境中维护一个「简历资源库」目录，建议包含三类子目录：

```
简历资源库/
├── 项目与经历/     # 每段经历一个 .md 文件，含方向标签
├── 学术成果/       # 论文、专利、可量化成果
└── 基础信息/       # 教育背景.md、技能与证书.md（固定模块）
```

> 实际路径以用户环境为准；AI 执行时先询问用户资源库位置，不要假设固定路径。

## 资源文件组织示例

### 项目与经历（示例结构，每段经历一个文件）

| 文件 | 方向标签 | 典型JD匹配 |
|------|---------|-----------|
| 01-XX仓储实习.md | 仓储管理、物料管控、成本控制 | 供应链、物流运营、仓储岗 |
| 02-XX选址优化项目.md | 运筹选址、成本优化、多式联运 | 物流规划、选址分析、交通优化 |
| 03-XX运营岗位.md | 安全运营、标准化执行 | 央企通用、素质项 |
| 04-XX信息采集系统.md | 数据工程、ETL、NLP | 数据岗、信息化岗 |

标签规则：方向标签是简历匹配的索引，写文件时按 JD 常见措辞打标签（如"仓储管理""成本控制"），不要用内部代号。

### 学术成果（示例）

| 文件 | 关键词 | 匹配方向 |
|------|-------|---------|
| 论文-XX效率研究.md | 面板数据、效率评价、SBM | 数据分析、研究岗 |

### 基础信息（固定模块）

| 文件 | 内容 |
|------|------|
| 教育背景.md | 完整学历链（最高学历→交换→本科→专科，按实际） |
| 技能与证书.md | 软件工具、资质证书、核心优势标签 |

## 选材原则

1. **JD核心词 → 资源库标签匹配**：先看JD反复出现的动词和名词，去资源库里找对应标签的经历
2. **最多选4-5段经历**：一页简历的极限，多了必然超页或挤压描述
3. **按匹配度排序，不是按时间排序**：最相关经历置顶
4. **不相关的果断砍掉**：零售经历不放技术岗、AI平台不放传统仓储岗

## 真实性红线

- `独立开发/构建` → 必须是真正从零做的
- `二次开发/魔改定制` → 基于开源框架改的，必须如实标注
- `项目负责人` → 课程/学术项目可以有此角色
- `参与/协助` → 兼职或辅助角色
- 不确定的标注「待确认」，不进入最终简历

## 学历规则

- **保留完整学习经历，不删第一学历**
- 第一学历简写：学校 + 专业 + 时间，无需课程细节
- 最高学历与中间学历可展开课程/学术成果
