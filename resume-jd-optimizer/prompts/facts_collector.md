# 事实采集 Prompt

## 任务

针对用户新提供的一段经历，逐条提取原子级原始事实，写入 `resume_facts.yml`。不做任何美化、省略或推断。

## 采集规则

1. 用户的第一人称描述为核心事实来源，逐句拆解为原子事实
2. 每条 raw_fact 是一句可独立验证的真实陈述，不捆绑
3. 不美化、不省略、不推断用户未明确说出的内容
4. 不利事实（如陪标、未中标、未落地）照实记录，不隐藏
5. 不用记录的默认假设：
   - 基础 Office 操作（文件编制、数据整理）为用户默认具备的能力，不逐条录入
   - 只有涉及特定工具（AutoCAD、Python 等）时，才在事实中注明工具名称
6. 采集完毕逐条与用户确认

## 采集框架

对每条新经历，按以下维度逐项询问：

1. **背景**：什么时间、什么组织/公司、你的角色
2. **起因**：为什么参与、被谁安排、主动还是被动
3. **动作**：你具体做了什么（动词+对象+工具），从开始到结束
4. **边界**：哪些是你做的、哪些是团队做的、哪些你只旁观
5. **结果**：是否完成、是否落地、是否中标/通过、是否收到反馈
6. **证据**：是否有文档、截图、邮件留痕

## 输出

```yaml
- id: {kebab-case-id}
  title: "{经历标题}"
  organization: "{所属组织/公司}"
  role: "{你的角色}"
  date: "{时间段}"
  jd_tags: [{逗号分隔的关键词标签}]
  evidence_dir: null
  raw_facts:
    - {原子事实1}
    - {原子事实2}
```

- `id` 使用 kebab-case
- `jd_tags` 用于后续 JD 匹配，列出该经历可能对接的岗位关键词
- `evidence_dir` 若用户有素材文件，填写 evidence 子目录名；否则 null
