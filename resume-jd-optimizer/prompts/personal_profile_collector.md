# 个人信息采集与管理 Prompt

## 任务

帮助用户建立并维护一份完整的个人信息档案，覆盖中国大陆国企、央企、事业单位招聘网申表单常见字段。本模块独立于简历优化工作流，但与之配合使用。

## 字段体系

按 `templates/personal_profile_template.md` 定义的字段结构，分为四类：

1. **基本信息**：姓名、性别、出生日期、身份证号、民族、籍贯、户籍性质、政治面貌、婚姻状态、健康状况、身高、体重、辨色力
2. **学历信息**：最高学历、毕业院校、所学专业、专业方向、毕业时间
3. **联系方式**：手机号码、电子邮箱、通讯地址、邮编
4. **家庭成员**：与本人关系、姓名、工作单位、从事工作/职务（可多条）

## 收集规则

1. 用户首次使用个人信息模块时，逐类询问。每类合并一次提问，不超过 8 个字段。
2. 身份证号、手机号码、电子邮箱、详细住址为敏感字段，收集时提示用户：仅在填表输出时使用原文，简历正文中自动脱敏。
3. 家庭成员支持多条记录，每条四列固定结构。
4. 字段值为空时标注「待补充」，不编造。
5. 用户提供的信息直接记录，不做推断、不修改（如户籍性质的「农业」不改为「农村」）。

## 验证规则

收集完成后逐条确认：

- 身份证号 18 位格式校验
- 毕业时间逻辑（不早于出生日期 + 标准学制）
- 政治面貌与年龄的合理性
- 身高体重数值范围合理性
- 家庭成员信息完整度（四列齐全）

发现异常时不自动修正，而是标注后反馈用户确认。

## 输出规则

**简历场景**（配合 resume_rewriter 使用）：
- 姓名、学校、专业、学历进入简历头部
- 手机、邮箱脱敏后可选展示
- 身份证号、详细住址、家庭成员不写入简历正文
- 籍贯、政治面貌等视招聘方要求决定是否写入

**网申填表场景**（独立使用）：
- 按目标平台要求的字段输出完整信息
- 敏感字段输出前提示用户确认
- 格式与目标平台字段名称对齐

## 与简历优化工作流的协作

1. 个人信息档案独立维护，不随 JD 版本变化而改变。
2. 简历重写时自动从个人信息档案提取姓名、学校、专业、学历。
3. 网申填表时，用户可指定目标平台（如「中国铁路人才招聘网」），按该平台字段要求输出。
4. 个人信息更新时，不触发简历重新优化，但触发用户提醒「简历头部信息已过时，是否同步更新」。
