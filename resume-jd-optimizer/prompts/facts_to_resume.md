# 事实到简历生成 Prompt

## 任务

从 `resume_facts.yml` 的原始事实出发，按照目标 JD 和用户指定的优化档位，生成简历正文中的经历描述。

## 输入

- `resume_facts.yml`（统一事实数据库）
- 目标 JD 解析结果
- 优化档位：`faithful` / `conservative` / `standard` / `proactive`
- 目标岗位名称与公司

## 档位行为

### faithful（如实）

- raw_facts 逐条映射为简历描述，不省略、不重组、不加修饰
- 不利背景如实呈现
- 适用于面试自用、内部复盘

### conservative（保守）

- 省略不利背景（如陪标、未中标、未落地、已内定）
- 动词使用 raw_facts 中的真实强度
- 不添加推断动作或过程描述
- 与 JD 无关的 raw_facts 保留但可后置
- 适用于网申系统、国企央企

### standard（标准）

- 省略不利背景
- 动词可升半级：前提是 raw_facts 中存在可支撑的动作基础
  - "被叫去签字出价" → "参与投标流程"
  - "旁观了解全流程" → "完整经历从公告到开标全过程"
  - "AI 辅助搭架子" → "独立构建系统"（⚠️ 因用户有自主开发能力，此处可升半级）
- 可补充合理过程描述：从 raw_facts 的动作推断必然伴随的过程性工作
  - "整理资质材料" ← 投标必然环节，事实基础是参与投标
  - "协调多部门收集材料" ← 投标必然环节
- 与 JD 无关的 raw_facts 后置或简写
- 适用于大多数投递场景

### proactive（进取）

- 与 standard 规则相同
- 额外操作：
  - 经历按时间倒叙排列，最相关的经历写得更详细、条目更多（通过详略体现匹配度，不通过排序位置）
  - 次要经历可大幅简写或降为一行
  - 与 JD 高度匹配的 jd_tags 可以融入描述
- 适用于高度匹配的热门岗位

## 通用硬规则

1. **学历完整性**：教育背景四段学历全部保留，只简写不删除
2. **贡献动词下限**：不满足事实门槛不得升级动词（支持<参与<负责<推动<主导）
3. **不利背景过滤**：raw_facts 中的「陪标」「已内定」「未中标」「未落地」「未收到反馈」在任何非 faithful 档位中自动过滤，不进入简历正文
4. **通用能力不录入**：基础 Office 操作默认为用户具备的能力，不单独作为 raw_fact 扩写
5. **每条经历优先结构**：业务背景 + 个人动作 + 方法/工具 + 可验证结果 + 自然 JD 关键词，不强求每条包含全部元素

## 输出

每条经历按以下优先级排列：

1. 按时间倒序（最新的在前，按结束时间从新到旧）
2. 匹配度通过详略体现：最相关的经历写详细、条目多，低相关的写简短
3. raw_facts 单薄的经历可降为一行甚至省略

输出格式遵循 `templates/` 中对应模板，经历描述使用 Typst 兼容的 Markdown 列表语法。
